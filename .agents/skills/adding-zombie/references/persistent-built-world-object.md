# 僵尸部署的持久世界对象

适用于冰墙、路障、炮台等“由僵尸施工，但完成后不再依附建造者”的对象。附着在僵尸身上、随宿主死亡的装备不走本契约；固定格共享通路继续使用 `SKILL.md` 的 Board 格对象契约。

## 所有权与部署边沿

- 对象使用轻量 `GameObject`；`GameObjectManager` 持强所有权，`Board` 只持 `weak_ptr` 并提供唯一查询、添加和移除入口。建造者只保存自己的施工 phase、倒计时和必要的预定位置，不持对象强引用。
- 若半成品也参与碰撞，施工开始就是第一原子提交点：Board 先复核行、位置和唯一上限，再创建带 `constructionComplete=false + builderID` 的对象。施工完成在同一对象上原子硬化并清除 builderID，禁止销毁重建；是否回满生命由玩法规格明确，但绘制顺序、对象身份和引用必须保留。若半成品不参与玩法，仍可只在完工边沿一次性创建。
- 完成前死亡、失头、魅惑、半成品被摧毁或能力门禁失效时，按规格取消或暂停施工；由对象保存的稳定 builderID 负责孤儿回收，建造者不缓存裸指针。完成后清除关联，建造者死亡不得顺带删除对象。外部清场、融化或对象自身死亡只调用 Board 移除入口。

## 碰撞与伤害

- 若对象应先于僵尸拦截直线弹丸，在弹丸本帧运动线段上求最早对象命中，并在进入既有僵尸 `CollisionSystem` 回调前结算；不能只检测帧末点，否则高速或倍速下会穿透。未显式锁定对象的抛射、篮球等仍以运动/结算语义绕过，不在对象类维护弹丸品种表。
- 若自动投手需要优先攻击对象，由植物在发射边沿把显式锁定标志写入通用弹道状态；锁定弹跳过墙后僵尸，落点按对象允许移动余量复核同行对象，原对象消失时只落空而不改投。该标志必须入档并在对象池复位，禁止只从弹种或落点坐标反推目标意图。
- 对象暴露普通直击、元素倍率和盐蚀等语义窄入口；弹丸负责表达攻击来源，对象负责决定自身承伤。命中对象后是否消耗弹丸、是否产生穿透，由原弹丸合同决定。
- 对象移动或阻挡植物时，以实际 collider/视觉边界求停止位置；逻辑格与视觉偏移保持分离，不复制僵尸攻击框。

## 存档与验证

- Board 独立保存对象的行、稳定位置、当前/最大生命、小数伤害余量以及半成品的完成态/builderID；建造者 `SaveExtraData` 另存施工 phase、剩余时间、预定位置和已用标志。旧档缺完成态时默认按既有完整对象恢复；新档中施工 phase 与半成品关联不一致时回收孤儿或取消能力，禁止重复部署。
- 每波上限由正式波次 resolver/Board 计数拥有，换波清零并入档；AutoTest 直造保持确定性且不偷偷消费上限。
- AutoTest 至少覆盖半成品立即承伤、施工中快照、施工者死亡拆半成品、完工硬化、完成后建造者死亡留对象、对象自身快照、直线弹优先、绕过弹不命中、特殊破层、唯一/每波上限与换波重置。对象有新贴图或粒子时，同时断言资源键并检查默认可见截图；只有实际改到渲染后端或跨后端提交实现时，才加跑 `-NoInstance` 与强制 OpenGL。
