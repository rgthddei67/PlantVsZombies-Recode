# 僵尸部署的持久世界对象

适用于冰墙、路障、炮台等“由僵尸施工，但完成后不再依附建造者”的对象。附着在僵尸身上、随宿主死亡的装备不走本契约；固定格共享通路继续使用 `SKILL.md` 的 Board 格对象契约。

## 所有权与部署边沿

- 对象使用轻量 `GameObject`；`GameObjectManager` 持强所有权，`Board` 只持 `weak_ptr` 并提供唯一查询、添加和移除入口。建造者只保存自己的施工 phase、倒计时和必要的预定位置，不持有已完成对象的强引用。
- 施工完成必须经 Board 单一入口原子提交：先复核行、位置、唯一数量或每波上限，再一次性创建对象并把建造者切到完成态。失败不得留下半对象，也不得消费“已施工”次数。
- 完成前死亡、失头、魅惑或能力门禁失效时，按规格取消或暂停施工；完成后建造者死亡不得顺带删除对象。外部清场、融化或对象自身死亡只调用 Board 移除入口。

## 碰撞与伤害

- 若对象应先于僵尸拦截直线弹丸，在弹丸本帧运动线段上求最早对象命中，并在进入既有僵尸 `CollisionSystem` 回调前结算；不能只检测帧末点，否则高速或倍速下会穿透。抛射、篮球等明确绕过类型以运动/结算语义排除，不在对象类维护弹丸品种表。
- 对象暴露普通直击、元素倍率和盐蚀等语义窄入口；弹丸负责表达攻击来源，对象负责决定自身承伤。命中对象后是否消耗弹丸、是否产生穿透，由原弹丸合同决定。
- 对象移动或阻挡植物时，以实际 collider/视觉边界求停止位置；逻辑格与视觉偏移保持分离，不复制僵尸攻击框。

## 存档与验证

- Board 独立保存对象的行、稳定位置、当前/最大生命及小数伤害余量；建造者 `SaveExtraData` 另存施工 phase、剩余时间、预定位置和已用标志。读取旧档时，中性默认不得凭空生成对象；待施工状态与现存唯一对象冲突时修复为已完成或取消，禁止重复部署。
- 每波上限由正式波次 resolver/Board 计数拥有，换波清零并入档；AutoTest 直造保持确定性且不偷偷消费上限。
- AutoTest 至少覆盖施工中快照、完成后建造者死亡、对象自身快照、直线弹优先、绕过弹不命中、特殊破层、唯一/每波上限与换波重置。对象有新贴图或粒子时，同时断言资源键，并检查默认实例化与 `-NoInstance` 同步截图。
