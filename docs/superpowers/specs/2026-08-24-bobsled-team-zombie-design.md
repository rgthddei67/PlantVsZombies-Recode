# 雪橇车队僵尸设计规格

## 目标

在第七大关加入 `ZOMBIE_BOBSLED_TEAM`（雪橇车队僵尸）。一次正式出怪只占一个候选和一份点数，入场后组成四名乘员的一辆雪橇；它只在 Board 当前真实冻土上保持高速滑行，离开冻土或撞上植物后整队下车。

难度来自落点整形：普通碰撞会把成员投向本行更深处和相邻行，迫使玩家同时修补多行；仍存活且锚定中的雪锚果把四人全部约束在自身右侧同一行普通下车，并在承受碰撞伤害后继续按剩余生命决定后续资格。僵尸侧只调用植物基类的 `ResolveWinterGroundImpact(COLLISION)`，不得识别雪锚果类型。

动画直接导入原版 `Zombie_bobsled.reanim` 和对应部件图；雪橇车身使用原版 `Zombie_bobsled_inside.png`、`Zombie_bobsled1.png`～`Zombie_bobsled4.png`。不重新绘制或程序染色。

主人指定并确认的帧事件采用本项目现有减一口径：

- 第 133 帧结束死亡动画并回收实体。
- 第 151、169 帧各结算一次啃食。
- 下车由阶段计时和 `anim_jump` 轨道推进，不新增动画帧事件。

## 编队身份与出生

四名乘员都使用同一个稳定枚举、工厂类和图鉴身份，不为跟随者增加第二种伪僵尸：

- 队长保存三个成员 ID，负责雪橇耐久、滑行、碰撞请求和整队下车。
- 跟随者保存队长 ID 与 1～3 号槽位；乘雪橇时关闭自身碰撞，只同步队长位置和编队视觉高度。
- 队长首次正式更新时创建三名跟随者并立即写入角色，避免构造/读档阶段递归生队。
- 正式刷怪只对队长扣一次点数和每波上限；三名跟随者是同一队的组成部分，但仍各自计入场上僵尸总数、伤害、死亡和存档。

预览只显示一名骑手和完整雪橇，不创建临时跟随者。

## 三阶段状态机

### RIDING

- 队长使用约 275×115 的车辆碰撞框；跟随者碰撞关闭且不可被单独索敌。
- 四人播放 `anim_push`，雪橇和成员不接受魅惑、减速、冻结、黄油、麻痹或水草抓取。
- 队长按 60 px/秒向房屋滑行，并继续组合品种能力、天气和风向倍率；不复制或修改寒潮、冻土状态。
- 队长当前前缘位于 `GetFirstFrozenColumn()` 的冻融线左侧，或冻土完全消失时，立即进入未约束下车。
- 只有队长的 300 雪橇耐久承受普通命中；三档车辆图按耐久派生。耐久归零会触发未约束下车，溢出伤害继续进入队长本体。
- 乘雪橇期间任一成员被直杀、化灰或本体归零，整队立即死亡，保持原版“车上共命”规则。

### LANDING

- 四人播放 `anim_jump`，以 1.5 秒位置插值和抛物线视觉高度前往各自落点；不用新增动画帧事件。
- 所有成员均可被伤害，但在落地前仍保持雪橇阶段的控制免疫，避免半空魅惑或冻结破坏编队交叉引用。
- 雪橇换为 `Zombie_bobsled4` 并在过渡后段淡出。前后层按原版队员槽位交错绘制；默认实例和 `-NoInstance` 路径都必须保序。
- 过渡结束后启用普通碰撞、清除车队防具并进入 `WALKING`。

### WALKING

四名乘员成为同种普通地面僵尸，独立走路、啃食、受控、魅惑、断肢、断头和死亡。队长不再代表雪橇，队伍关系只保留为历史交叉引用，不会再次合队。

## 碰撞与落点

队长在 `RIDING` 与植物首次重叠时，先确定同格最高可吃植物，再以通用接口原子请求一次 `COLLISION`：

1. 保存植物碰撞箱右缘作为落点基准。
2. 调用 `plant->ResolveWinterGroundImpact(COLLISION)`。
3. 由雪橇以 `DamageSource::ZOMBIE` 对该植物造成 1200 伤害。
4. 根据响应选择同一帧提交的四个落点，然后进入 `LANDING`。

若 `intercepted && containsScatter`：四人全部保持原行，按从植物右侧向出生区方向的小间距依次落地；任何成员都不得越过植物或进入相邻行。

否则使用未约束散开：队长留在碰撞本行，第二人向房屋方向前插约一格，第三、第四人分别向上、下相邻行并略向房屋侧前插。边缘行缺失的相邻目标折回原行，但仍保留横向错位。冻融线下车和雪橇破坏同样使用未约束散开。

伤害、落点、雪橇阶段、音画和下车提交全部由僵尸拥有；植物只提供原子响应。若雪锚果没有锚定、已经死亡或所在格融化，接口返回中性结果并照常散开。响应发生在 1200 点碰撞伤害之前，因此将被本次伤害击杀的雪锚果仍能约束当前车队，之后不再生效。

## 断肢、断头与死亡

落地后的原版部件规则固定为：

- 断头前读取 `anim_head1` 世界锚点，随后隐藏 `anim_head1`、`anim_head2`，发射原版独立 `ZombieBobsledHead` 掉头粒子。
- 断臂前读取 `Zombie_outerarm_lower` 世界锚点，随后隐藏 `Zombie_outerarm_lower`、`Zombie_outerarm_hand`，把 `Zombie_dolphinrider_outerarm_upper` 替换成 `Zombie_bobsled_outerarm_upper2`，发射原版手臂部件掉落粒子。
- 两者复用现有肢体掉落音效；读档的 `ZombieItemUpdate` 必须重建同样的隐藏与换图终态。
- 死亡播放原版 `anim_death`，第 133 帧回收；车上整队死亡不逐人播放落地后的死亡时间线。

## 资源、存档与兼容

- `scripts/import_bobsled_team_assets.ps1` 从已确认的原版资源目录复制文件，并在复制前核对每个源文件 SHA-256；资源来源、目标键和哈希可复现。
- `resources.xml`、manifest、`ResourceKeys`、reanim 注册、粒子贴图注册和实际 `GetTexture(key,false)`/`HasReanimation` 断言形成闭环。
- 每名乘员保存角色、阶段、槽位、队长/成员 ID、是否已经生成编队、落地起止位置、计时和雪橇淡出状态；核心血量、防具、行、位置和 Animator 继续走通用存档。
- 读档只恢复稳定 ID 交叉引用，不重生跟随者、不重抽落点；孤儿车上成员在全部实体恢复后的首次更新安全降级为原地普通下车。
- 该类型不得进入泳池水路；寒潮地图是首发场景，其他平地关卡若通过开发入口直造而没有冻土，会立即未约束下车。

## 出怪编排

雪橇车队在 7-2 首次教学，因为玩家已经持有 7-1 奖励雪锚果。当前第七大关表按以下节奏追加该类型：

- 7-2：单机制首次教学，精简既有池并加入雪橇车队。
- 7-3：第一次无奖励复习，继续出现。
- 7-4：暂时不出现，为下一株植物教学留空间。
- 7-5、7-7、7-8：作为跨行压力与后续重点敌人组合。
- 7-6 暂停雪橇，完整教学气象干扰；7-9 综合关再次加入。

正式波次解析器每波最多接纳三队，超过上限的候选跳过且不扣预算。跟随者直造不消费该上限。

## AutoTest 验收矩阵

1. 资源：reanim、19 张部件图、5 张雪橇图、专属掉头图、断臂图与两份粒子 XML 实际可加载。
2. 出生：一个正式队长在首帧后形成四个稳定 ID、一个车辆碰撞体和三个关闭碰撞的跟随者。
3. 冻土：只在真实冻结列滑行；冻土消失或穿过冻融线时未约束散开。
4. 普通碰撞：植物承受 1200 僵尸伤害，成员出现本行前插和相邻行落点。
5. 雪锚果：生命 3000→1800 后仍保持锚定资格、四人都在植物右侧同排；植物侧专项另锁定 1800→600 与致死一撞仍响应、死亡后失效。
6. 雪橇耐久：300/三档贴图、破坏时散开、溢出进入本体。
7. 控制：车上拒绝魅惑、减速、冻结、黄油、麻痹和水草；落地后全部恢复普通规则。
8. 共命与普通死亡：车上任一人死亡整队清除；落地后互不连死，133 帧回收。
9. 部件：151/169 啃食，专属断头/断臂锚点、换图、粒子及读档外观恢复。
10. 存档：`RIDING` 与 `LANDING` 中途往返不重复生队、不换落点、不丢耐久和 Animator 进度。
11. 编排：7-2/7-3/7-5/7-7/7-8/7-9 出怪表、生存第 10 轮与每波三队上限。
12. 可见：`clang-release` 当前桌面默认实例和 `-NoInstance` 各同步截图检查车体前后层、普通散开、雪锚约束和部件掉落。
