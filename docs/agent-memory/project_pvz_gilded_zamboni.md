# 鎏金冰车僵尸与黄色冰道

## 当前实现

`ZOMBIE_GILDED_ZAMBONI` 使用金黄色车体、驾驶员衣物和帽子，2200 HP，基础驱动倍率 0.72，
比普通冰车慢。正式波次每波最多生成 1 只，计数随 Board 存档并只在推进新波时清零；
AutoTest 的显式直造不消耗额度。冒险 3-6（level 24）为 20 波
`{normal, cone, bucket, zamboni, gilded zamboni}`。

车辆只碾压本行植物；黄色冰道仍尝试铺在本行与相邻两行，并在非水路保持 35 秒。
Board 分行保存黄色左缘/寿命，旧档缺字段为空；黄色与普通冰道重叠时先截短普通段再绘制
黄色段，因此玩家只看到黄色，且两者都禁止种植。

## 速度与受击

每个仍存活且实际覆盖目标的鎏金冰车都是一个独立速度来源。普通僵尸必须处在该来源已经铺过
的黄色区间；鎏金冰车本体另含短距离车身覆盖，使相邻车辆可互相影响。每层对能力、寒冰、
雨势、台风等非中性倍率分别应用“加速乘二、减速除二”，再把各分量相乘；中性 `1.0`
保持不变。两条活跃来源重叠会逐层放大，例如大雨 `1.4→2.8→5.6`、寒冰
`0.6→0.3→0.15`。来源死亡、车辆离开或范围变化后逐帧刷新层数。

自身连续 6/10/14 秒未受伤时基础蓄势为 ×2/×4/×8；任何本体伤害立即清零并回到 ×1，
自身黄色冰道也会强化这项能力，因此单来源下实际能力层为 ×4/×8/×8；最终能力倍率仍
封顶 ×8。计时器和每个来源的独立黄色左缘入僵尸扩展存档。

地刺只造成 100 本体伤害，不爆胎、不伤地刺；大嘴花不能吞下车辆，并由车辆覆写
`AdjustRejectedChomperBiteDamage()` 将统一默认值调整为每口 50 本体伤害。两者都通过车辆虚事件接入，
不在植物侧硬编码鎏金类型。寒冰仍可减速，冻结最终优先停格。

## 2026-07-27 黄色冰道来源专用索引

`Zombie::ComputeGoldenIceEffectStacks()` 原先由每只僵尸逐帧查询本行及相邻行：
首个 `ForEachZombieInRow()` 会在 `CleanupExpired()` 标脏后扫描全体僵尸重建行桶，
随后还要遍历三行候选并逐个 `dynamic_cast`。即使场上没有鎏金冰车，这项能力也会把
通用行索引拉进每帧热路径。

现在 `EntityRegistry` 在 `AddZombie()` 与 `AddZombieWithID()` 统一登记鎏金冰车的
ID→弱引用专用索引，每帧首查只从这张稀疏表生成活跃来源强引用快照；
`CleanupExpired()` 每帧释放快照，并随原有 30 帧清理周期裁掉过期弱引用。
目标仍即时复核来源当前行、活跃/死亡状态及 `ProvidesGoldenIceEffectAt()` 的精确覆盖，
零活跃来源时的 Board 持久黄冰回退也保持不变，因此进入、离开、来源死亡、范围变化和
多来源叠层语义未改变。复杂度从每目标扫描三行僵尸降为每目标只扫鎏金来源数，
并且该能力不再触发通用行索引重建；通用行索引的每帧标脏契约本身未修改。

`clang-playtest` 零警告构建通过。可见 `smoke_gilded_zamboni.json` 以 Seed 42 退出码 0；
新增用例确认跨相邻行两来源为 2 层、逐个击杀后依次变为 1 层，最后活跃来源清零时仍由
35 秒持久黄冰提供 1 层，`run.log` 以 `script finished OK` 结束。

## 2026-07-28 本行碾压调整

本行植物进入压扁态且三行黄色冰道全部激活；泳池场景另断言相邻陆路和水路植物均不被压，
水路仍按既有规则不铺冰。
