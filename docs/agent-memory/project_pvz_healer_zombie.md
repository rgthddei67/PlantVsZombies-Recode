# 第六大关急救员僵尸

## 玩法与数值

- `ZOMBIE_HEALER` 在 6-6 首次登场，复用普通僵尸骨架、移动和既有啃咬/死亡帧事件；本体 800、啃咬 50、权重 2400、`appearWave=3`、`survivalRound=7`，不新增动画帧事件。
- 出生从 6 秒共享冷却开始，施法前摇 1 秒。140px 内至少 3 名同阵营伤员（含自己）时，结算重扫并对全部目标的每个现存生命层恢复 60，不限制数量；否则锁定 280px 内一名非自己的伤员，每层恢复 300。只有实际恢复生命才进入完整冷却，目标失效或零治疗在 0.5 秒后重试。
- 单疗优先当前黑夜屋顶已锁定劫持者；其他目标按现存本体/一类/二类层的最低剩余比例、再按稳定实体 ID 排序。多名急救员用 `EntityManager` 有序弱索引协调同帧选择与单疗预留。该索引只镜像 `weak_ptr`，主 `mZombies` 仍保留所有实体，`ForEachZombieInRow` 与专用索引计数专项一致。

## 生命层、状态与交互

- 治疗分别夹紧现存且大于 0 的本体、头盔和盾牌；已掉落、磁吸或部署的装备不重建，气球 extra health 不参与。通用 `RefreshEquipmentPresentationAfterRepair()` 让各品种虚检查从当前耐久重新派生完整/轻损/重损贴图，修复了原先只能单向破损的显示合同。
- `IDLE/AREA/FOCUSED/DISABLED` 分别使用折叠、绿色三加号、紫色单加号和烧焦垂下标志。施法优先于啃食：原子平衡食客计数并停吃，治疗结束后仅在原目标仍有效且仍处于 6px 咬合间隙时恢复同一目标。
- 断头始终永久禁疗；有效难度 `<=2` 时断臂永久禁疗，`>2` 继续治疗。魅惑取消旧阵营目标/预留但保留冷却。预览固定 `IDLE` 与 6000ms 冷却，不推进决策、声音或粒子。
- 存档保存状态、冷却/重试/前摇、单疗目标、待恢复啃食目标和永久禁疗；读档修复无头、低难度无臂、零前摇施法等非法组合。

## 资源、出怪与验证

- 身体与四态标志、绿色加号/光环由 `scripts/generate_healer_assets.ps1` 可重复生成；粒子效果为 `HealerAreaHeal` / `HealerFocusedHeal`，持续 0.9 秒并上升 24px。主人复核后两种加号统一乘 0.7，单疗仍为群疗 1.5 倍且光环不缩放。
- 6-6 内部关卡 51 的第 3 波在正常预算外额外保底一只，普通池仍可自然选中；没有每波硬上限。图鉴在通关 6-6 后解锁，详情预览无逻辑副作用。
- 2026-08-14 `clang-release` 构建与 Win7 导入审计通过。当前桌面可见 `smoke_healer_focused/area/difficulty/coordination/eating_charm/spawnlists/armor_group/cancel/almanac/death` 均 exit 0，focused 的 `-NoInstance` 也通过；覆盖资源、双模式、0.7 粒子、六只群疗、五类护具、难度断臂、啃食恢复、魅惑、存档、取消重试、死亡、图鉴预览、6-6 保底与按行索引一致性。

## 延期候选

- 主人提出未来让主菜单轻量蒙特卡洛开关参与群疗/单疗和单疗目标选择。当前未实现；若接入，关闭开关必须回退现有确定性规则，开启时只在 6 秒决策边沿做有限候选 rollout。第一版可把“已锁定劫持者存活到处决边沿”建模为快照战略价值，无需复制完整处决状态机；预测尚未锁定与雷荷未来才需要扩展模型。
